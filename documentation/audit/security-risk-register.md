# Prioritised Bug and Vulnerability Register

**Scope note:** Severity reflects the impact of the observed condition in this local-notes app. “Confirmed” means the relevant code/configuration is present. “Potential” means an exploit or device behavior was not demonstrated. No passwords, signing secrets or personal data are included.

| ID | Severity | Status | Finding and affected evidence | Impact | Recommended correction and verification |
|---|---|---|---|---|---|
| SEC-01 | High | Confirmed configuration risk | AndroidManifest.xml sets allowBackup=true; app/src/main/res/xml/backup_rules.xml and data_extraction_rules.xml contain no effective excludes. DatabaseHelper stores SQLite DB in the normal database directory; SessionManager and WritingPromptRepository use SharedPreferences; NoteBackupFileWriter writes under filesDir. Android Auto Backup defaults include these app-owned files. | Account details, credential hashes/salts, session flags, encrypted note rows and manual ciphertext backups can participate in platform cloud or device transfer. Keystore aliases are not app files and may not transfer with the database, leaving restored notes undecryptable. This also conflicts with a strictly “local-only” user expectation. | Decide whether to disable/exclude platform backup or implement an explicit restorable, user-controlled encrypted export. Define both legacy and API 31+ rules and transfer rules. Test backup/restore on API 30 and API 31+; verify what files are present and whether keys/data can be recovered. Official reference: https://developer.android.com/identity/data/autobackup |
| REL-01 | High | Confirmed performance/reliability risk | LoginActivity.handleLogin and RegisterActivity.handleRegistration call PasswordHasher and UserRepository from click handlers. DashboardActivity, NoteEditorActivity, NotesListActivity, SearchActivity and NoteDetailActivity call NoteRepository synchronously. NoteRepository decrypts database rows in cursor mapping. | PBKDF2 (310,000 rounds), SQLite and multiple AES operations block the main thread. Slow devices or large notes can cause visible freezes, missed input and ANRs. | Move work to Dispatchers.IO or a managed executor and expose loading/result state through lifecycle-aware ViewModel/repository APIs. Add tests and profile login, list, search and editor on low-end emulator with large data. |
| SEC-02 | Medium | Potential integrity-hardening gap | EncryptionManager uses AES/GCM/NoPadding but supplies no AAD associated with user ID, note ID or title/content field. | GCM authenticates ciphertext bytes. A party with ability to rewrite the app-private database could copy a valid ciphertext/IV pair from another row in the same account; authentication can still succeed for the transplanted value. No remote path to write the DB was established. | Supply deterministic AAD binding account ID, note ID, schema/version and field name during both encrypt/decrypt. Plan a migration/version strategy. Test that row/field transplant fails authentication. |
| SEC-03 | Medium | Confirmed behavior; key loss itself is unrecoverable | EncryptionManager.getOrCreateKey is used for both encrypt and decrypt. If alias is absent, it creates a fresh key before attempting decryption. Privacy strings disclose that data cannot be recovered if its key is removed/unavailable. | Existing ciphertext remains unreadable; a read can create a replacement alias that has no relation to the old ciphertext, obscuring original key-loss diagnosis. | Separate getOrCreateForEncryption from getExistingForDecryption. Do not generate on read. Return a typed permanent-unavailable state and document restore limits. Test deleted alias, reinstall, device restore and authentication failure. |
| REL-02 | Medium | Confirmed scalability issue | NoteRepository.getNotes decrypts selected records in a loop. SearchActivity calls getNotes on every TextWatcher change. NotesAdapter.submitList calls notifyDataSetChanged. Dashboard refresh reads recent notes and the full list, then rebuilds adapters. | Search latency and UI jank grow with account size; the UI performs unnecessary decryptions and full row rebinding. | Debounce search, query metadata/ciphertext by limit, decrypt off-main, use ListAdapter/DiffUtil, update adapters incrementally, and query pinned/recent/count independently. Verify with 1k+ synthetic notes and frame/latency measurements. |
| AUTH-01 | Medium | Confirmed limitation | SessionManager stores user ID, email, full name, login flag and failed-attempt counters in MODE_PRIVATE SharedPreferences. These files are in default Auto Backup scope. Local throttling is also stored in the same preferences. | App-private preferences are inaccessible to ordinary other apps, but backup/root/compromised-device contexts can expose or restore local session state. Lockout state can be changed if app storage is compromised. | Exclude session/lockout preferences from transferable backup; clear login sessions on restore. Keep sensitive auth tokens out of ordinary prefs. This is a local threat-model limitation, not an ordinary cross-app read vulnerability. |
| PERM-01 | Medium | Confirmed UX/requirements gap | SettingsActivity shows custom permission rationale only when shouldShowRequestPermissionRationale returns true. On first request it invokes the system dialog directly. | User may see a permission prompt without the app’s own explanation of why notifications improve backup status. | Show a concise pre-permission explanation on first request; retain current option to back up without notifications. Execute first request, denial, second request and permanent-denial settings flows. |
| INT-01 | Medium | Confirmed requirement gap; sensitive flow intentionally disabled | NoteDetailActivity share control only shows a Toast. No ACTION_SEND or chooser exists. The normal note list also opens the editor, so detail screen is not currently reachable. | User cannot share/export a note through Android’s share sheet; assignment implicit-intent requirement is not met. No plaintext exposure through this route was observed. | If sharing is required, design explicit user confirmation and a minimal plaintext export destination flow with clear warning. Revalidate that recipient handoff is intentional and test cancellation/chooser. Otherwise remove the share affordance and document the unsupported feature. |
| DATA-01 | Medium | Confirmed upgrade limitation; migration outcome untested | DatabaseHelper.onUpgrade renames an existing notes table to notes_legacy_vN and creates the new schema without migrating rows. | Existing notes may remain in a legacy table but become invisible to the new repository; upgrades can look like data loss. | Write a versioned migration or clearly wipe only after explicit user consent and backup. Test upgrades from each supported schema version with preserved user/note counts and ownership. |
| UI-01 | Low/Medium | Confirmed functional issue | SearchActivity never makes btnClearSearch visible; XML declares it GONE. DashboardActivity derives pinned notes from getRecentNotes(userId, 5). | Clear control is unavailable; pinned notes outside the recent five are omitted from dashboard. | Toggle clear visibility from query state; add a repository pinned query independent of recent list. Cover empty/query/pinned older-note cases with UI/integration tests. |
| UI-02 | Low/Medium | Confirmed navigation/feedback issue | NoteDetailActivity is registered but no normal note selection launches it; save status TextView is static; bottom navigation starts new Activities without stack reuse/finish. | Detail actions are inaccessible; static text can misrepresent persistence; repeated navigation may build duplicate screens/back-stack entries. | Connect destinations and derive save status from operation result; choose a singleTask/backstack policy or use fragments/navigation component. Test repeated tab selection/back behavior. |
| PERF-01 | Low | Confirmed inefficiency | NoteDetailActivity loads in onCreate and again in onResume. RecyclerView item binding and time formatting occur on each full refresh. | Duplicate decrypt/database work and avoidable allocation/formatting. | Load once per data change, use lifecycle result/refresh signal, and profile repeated navigation. |
| NET-01 | Low/Medium | Confirmed defensive-limit defect | WritingPromptRepository reads response with readText() and checks MAX_RESPONSE_CHARS afterward. | The limit does not constrain peak memory consumed by a large response. The service endpoint is HTTPS but externally controlled. | Read a bounded stream and abort once byte/character limit is exceeded. Test oversized, malformed, non-2xx and slow responses. |
| REL-03 | Medium | Confirmed release readiness gap | app/build.gradle.kts declares no release signingConfig. Gradle versionCode/versionName differ from app_version string. .gitignore does not name keystore/property extensions. | Release build/signature and displayed version cannot be trusted as configured; future credentials could accidentally be committed. | Align version metadata; configure signing from untracked local properties/environment/CI secrets; ignore keystore files and signing property files; verify signed APK/AAB with apksigner and install. Never commit the keystore/password. |
| UI-03 | Medium | Confirmed design/assignment gap | No app View overrides onDraw; PasswordStrengthMeter only sets horizontal orientation. No app animation API usage; four XML animations have no references. | Required custom illustration and animation behavior are absent; registration reserves a nonfunctional strength meter slot. | Implement theme-aware Canvas view and at least two purposeful animations; honor animator scale; test resizing and reduced motion. |

## Security-positive evidence

- Password DB schema has hash and salt fields, not plaintext password field.
- PasswordHasher creates 16-byte random salts and compares derived bytes with MessageDigest.isEqual.
- SQL predicates use placeholders; no user-provided SQL string concatenation was found in inspected production paths.
- Note ciphertext is generated before SQLite insert/update and each value stores its IV.
- SecureNotesProvider is exported=false with URI grants disabled and exposes ciphertext columns only.
- Manifest components other than launcher are non-exported.
- No production Kotlin logging of note text/password or hardcoded AES key/API secret was found in inspected code.
- HTTPS is used for writing-prompt requests; no account/note data is added to the request.

These positives do not cancel the backup configuration or the lack of runtime verification.
